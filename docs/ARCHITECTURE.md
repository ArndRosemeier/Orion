# Architecture — seam index (Orion)

**Checkable entries, not prose.** A landing that adds/moves/deletes a seam updates its row **in the same commit**.

Vite + React + TypeScript SPA. Product direction (ledger row 2): a fractal explorer with arbitrarily deep zoom built on an adaptive **precision ladder**, GPU-first behind one backend seam.

## Layer map

| Layer                                | Owns                                                                          | Must not                                                      |
| ------------------------------------ | ----------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `src/` entry (`main.tsx`, `App.tsx`) | wiring / shell UI                                                             | grow into a junk drawer                                       |
| `src/lib/`                           | shared helpers, pure utilities                                                | duplicate domain logic; import React unless UI-specific       |
| `src/domain/`                        | pure math, engines, view model — the precision ladder lives here              | import React/UI; touch `window`/`document`; read env directly |
| `src/domain/numeric/`                | arbitrary-precision scalar + complex arithmetic, working-precision derivation | know about fractals or views                                  |
| `src/domain/engines/`                | escape-time engines (direct now; perturbation/series/GPU later)               | own rendering, tiling or UI concerns                          |
| `src/domain/view/`                   | viewport ↔ complex plane mapping                                              | know how pixels get drawn                                     |
| `src/ui/`                            | presentation, local UI state, viewport measurement, render backing budget     | import data/store internals directly (route via domain/lib)   |
| `src/styles/`                        | the dark theme: design tokens + global reset/shell CSS                        | hard-code a colour/spacing value that a token already owns    |
| `src/env.ts`                         | env parse (Zod) at the boundary                                               | ad-hoc `import.meta.env` reads scattered elsewhere            |

## Gotchas

- Relative paths in a multi-worktree brief resolve against the **main** workspace — use absolute paths under the worktree.
- Docs (`DECISION-LEDGER`, this file, `TESTING`) are **not** file-disjoint across parallel writers — assign ledger row numbers in the brief.
- OpenCode worktrees live under `/tmp`; ≤2 writers; one gate lock at a time.
- **No GPU on this box.** Use headless Chrome + SwiftShader for GPU _correctness_; never for timing. See `TESTING.md`.
- Rust build steps must call `~/.cargo/bin/cargo` explicitly — it is not on the default PATH.
- A reference orbit must hold `maxIterations + 1` values (`Z_0 .. Z_maxIterations`). Ask for fewer and every pixel past the end correctly reports `orbit-exhausted` and falls back to repair — slow, not wrong.
- A reference orbit for a point _outside_ the set is short, because it stops at escape. That is normal and is what the `orbit-exhausted` repair path exists for.
