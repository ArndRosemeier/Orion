# How we do it — living catalog (Orion)

When you add or change shared logic, **update this doc in the same commit**.
AGENTS.md only points here — do not paste encyclopedias into always-on rules.

## House patterns (5–15 max, link to code)

1. **Search before invent** — grep + this catalog → extend canonical → only then create + register here.
2. **Schema at boundaries** — Zod; `z.infer` as SSOT; no hand-copied DTOs. See `src/env.ts`.
3. **COPIES line** — every landing reports fold-or-single-site explicitly.
4. **No silent fallbacks** — fail loud; visible errors.
5. **Mutation-check every pin** — break the code it guards, watch it go red, restore. Landing 2: 9/9 caught. Landing 3: 9/9 caught — including two _blind spots_ the first pass exposed (see 10).
6. **One rounding rule** — half away from zero, everywhere, in ONE implementation (`divideRounded`); every lossy path expresses itself as a division by a power of two. Mixed rounding modes are a silent precision leak. See `src/domain/numeric/bigfixed.ts`.
7. **Derive precision from the scale, never from the artifact** — a coarse artifact cannot report what it needs. See `fracBitsForScaleExponent` vs `fracBitsForPixelSize`.
8. **Never compare across representations** — assert the invariant in the exact type; a float projection is display-only. _Incident (landing 2):_ `escapeDirect` threw a false "escaped with |z|² = 4" because a rounded double was compared against an exact threshold.
9. **Reject loudly at construction** — `makeView` refuses a view it cannot resolve instead of letting a renderer draw a field of identical samples.
10. **Pin the sign and the extremes, not just the middle** — a mutation that only misbehaves for negative inputs or at extreme exponent gaps will survive a test suite built from typical values. _Incident (landing 3):_ two mutations stayed green until pins were added for a negative `fromBigFixed` and for an exponent gap wider than the double range.
11. **Verify a numerical claim by measuring it** — do not pin what you derived by hand. _Incident (landing 3):_ "the offset makes the orbit escape" was derived, tested, and false; a diagnostic run showed the point is inside the set. The true property (precision buys iterations) replaced it.
12. **A test whose worst case is an exact zero cannot pin a threshold** — `0 < anything` fires under any positive bound, so the bound goes untested. Extract the comparison and pin values either side of it. _Incident (landing 4):_ disabling the glitch threshold to `2^-900` stayed green until `isGlitched` was pinned at `2^-25` and `2^-23`.
13. **Diagnose a discrepancy before relaxing it** — every tolerance in a pin should name the mechanism it absorbs. _Incident (landing 4):_ a 6e-6 smooth-count difference was traced to delta error amplifying once `\|d\| > \|Z\|`; the exact iteration-count pin stayed untouched and only the sub-iteration tolerance was set from the measurement.
14. **Check a known coordinate is where you think it is** — a "famous deep-zoom point" may sit inside the set, where nothing escapes and a differential test proves nothing. Assert non-degeneracy (escapes occurred, trusted pixels existed) in every survey-style pin. _Incident (landing 4):_ the seahorse coordinate gave `escaped=0` across three depths.
15. **A bound of the wrong shape cannot be rescued by a constant** — if an estimate under-reports by 20+ orders of magnitude, the formula is wrong, not the safety factor. Replace estimation with validation against the thing being estimated. _Incident (landing 5):_ the geometric tail estimate for the series approximation was unsound by up to 7e25x.
16. **An accelerator that changes results must say so** — if a faster path cannot reproduce the baseline exactly, report that it ran (a field, a flag), never let it pass as the baseline. _Incident (landing 5):_ the series skip changes escape counts on near-boundary pixels; `escapePerturbedWithSeries` returns `skipped` and the limitation is pinned in both directions.
17. **Declare the baseline before measuring the accelerator** — "the fast path agrees with the slow path" is only meaningful once the slow path is itself pinned against the oracle. _Landing 5:_ the series mismatch was only diagnosable because `escapePerturbed` was already pinned equal to `escapeDirect` at 36/36.
18. **Never compute at less precision than the input carries** — rounding the input down destroys information the check cannot detect, because every later comparison agrees on the degraded value. _Incident (landing 6):_ the orbit-precision search started at `minFracBits` and silently rounded a 512-bit reference point to 64 bits.
19. **Verify a budget instead of deriving one** — a worst-case bound that is 12x too pessimistic is not a budget, it is an excuse to over-allocate, and tightening it into something usable would be a guess. Measure agreement instead. _Incident (landing 6):_ `53 + 2n` was replaced by computing at `F` and `2F` and comparing.
20. **Prove a kernel at a budget where precision cannot hide a bug** — a tolerance loose enough to absorb real accumulation will also absorb a flipped axis or an off-by-half-pixel origin. Pin the exact low-budget case separately from the divergence case. _Incident (landing 7):_ 8.8% divergence at 64 iterations looked systematic until 8 iterations returned exactly 0 mismatches, proving accumulation rather than a mapping bug.
21. **A cancelled job returns partial results and says so** — never a completed-looking result for work that was abandoned. Cancellation is a normal outcome, so it is a return value, not an exception; a _refusal_ (cannot do this at all) is still an exception. _Incident (landing 8):_ panning mid-render must abandon the stale frame, and the caller has to be able to tell that it did.
22. **A seam is a design until a second implementation goes through it** — the first implementation always shapes the interface around itself, and only the second reveals what was assumed. _Landing 9:_ the backend seam was unproven until WebGPU went through it, and doing so immediately surfaced the coordinate-convention split the interface had never had to express.
23. **An unchecked GPU dispatch is a silent wrong answer** — an invalid shader or binding does not throw; it makes the dispatch a no-op that leaves stale bytes in the output buffer, which look exactly like a result. Check `getCompilationInfo()` and run every dispatch inside a validation error scope. _Incident (landing 10):_ the first double-precision run returned 3072 wrong values and no error at all.
24. **Encode for the machine, accept for the human** — the canonical form should be exact and compact, but a hand-editable form costs little and makes a format usable. Make the choice explicit with a discriminator so no string is ambiguous. _Landing 11:_ base36 for links the app writes, decimal for links a person types, decided by a `fmt` field.
25. **Reuse a codec you already trust as your serialization boundary** — a format that survives a round trip in tests is a format that will survive a worker boundary. Inventing a second one creates a second thing to keep in sync. _Landing 12:_ the view crosses to the worker as the shareable-link fragment.
26. **A checked-in binary needs a source-drift check** — tests passing against a stale artifact is a silent divergence. Rebuild and compare bytes in the gate, and make the failure name the rebuild command. _Landing 13:_ `scripts/check-wasm.sh`, verified by appending one byte.
27. **When a faster carrier must match a slower one, forbid the optimizations that change results** — `fma` would be more accurate and would break bit-equality. Accuracy is not the goal when the goal is "the same answer, sooner". _Landing 13:_ the WASM kernel avoids `fma` and leaves `log2` to the host for exactly this reason.
28. **Guard a side effect with a statement, not `&&`** — `cond && doWork()` reads like a guard and silently skips the work when `cond` is false. _Incident (landing 14):_ `quality === "preview" && renderPerturbation(...)` meant the `exact` path rendered nothing at all.
29. **Assert against the oracle, not against a property a blank buffer also has** — "all values are finite" is satisfied by an untouched buffer of zeros, so it cannot detect that a render never happened. _Incident (landing 14):_ an all-zero tile passed the CPU backend's "every pixel resolved" check.

30. **A pin that compares a mechanism to itself cannot see a self-consistent bug** — "warm equals cold" runs the same key function on both sides, so a collision corrupts both images identically and the comparison passes. Compare against an **oracle computed independently of the mechanism**. _Incident (landing 15):_ dropping the row index from the tile-cache key stayed green under warm-vs-cold; it only died once the expected image was recomputed per pixel, straight from the view. Mutation-checking is what exposed this — the pin had been written, and looked right.
31. **Make the premise of an exact-comparison pin provable** — a bit-exact test is only as strong as its claim that two paths should agree. Build the case where the agreement is _exactly_ required (here: a view whose pixel centres are dyadic multiples of the sample spacing, so snapping is provably the identity), rather than a case where it is merely nearly true and the fuzzy part gets absorbed by a loose assertion. _Landing 15:_ pixel size 2^-8 and centre an odd multiple of 2^-9 make every product exact, which is what lets the cold render be compared to the oracle pixel for pixel.

32. **A pin that only passes the code's own current output is not a pin** — check the _magnitude_ it is meant to bound. _Incident (landing 16):_ three separate expectations in this landing were written from arithmetic I did in my head and were wrong (a depth of 2^-11 where the grid gives 2^-5, a 200-bit climb where 0.75^400 buys 166, a `navigationFracBits` figure of 136 where the linear rule gives 178). Each failed loudly against the code, which is the system working — but the habit to keep is: compute the expected number from the same _quantities_ the test uses, not from a remembered formula.
33. **A padding constant that is load-bearing must be pinned by the case that needs it** — if removing a constant turns a correct programme into a loud error, then that error case _is_ the pin. _Landing 16:_ `NAVIGATION_MARGIN_BITS` exists because the estimate is taken on the pre-rounding width, and re-multiplying it at the new precision can cross a power-of-two boundary and demand one more bit; at 2^-64 the floor stops absorbing that. Removing the margin fails the 400-step zoom test with a clear message rather than drawing mush, which is the outcome the design promises.
34. **Adding a resource to a shared backend means adding it to the ordering argument** — a per-render buffer is a per-render problem; a backend-owned buffer is shared by every render, including the ones that were _cancelled_ but whose GPU work is still queued. _Incident (landing 16):_ a staging buffer with a pending `mapAsync` was submitted into by the next render (`used in submit while pending map`). The mutation that removes the wait restores the failure, so the ordering is now pinned rather than remembered.

35. **Measure the hot loop before optimizing the cold one** — the plan for this landing was "the reference-orbit setup is expensive, cache it"; the measurement said the setup is 53ms and the per-pixel delta loop is 2472ms for one small tile, i.e. ~100% of the cost. The optimization that followed was in a different module than the one the plan named. _Landing 17:_ a first benchmark with zero deltas reported 0.02ms/px and nearly hid this, because a zero delta short-circuits every multiplication; the honest figure came from real pixel offsets.
36. **A pin that passes for the wrong reason is worse than no pin** — check that the scenario actually exercises the mechanism it names. _Landing 17:_ the crafted glitch-boundary case had an imaginary offset of 0.25 that dominated `|z|^2`, so no cancellation ever happened and the pin passed with no glitch at all; the real boundary case needs a negligible imaginary term (2^-81) before it tests anything. Two other pins in the same landing were inert under mutation for the same class of reason, and were found only by running the mutations.
37. **A binary artifact needs its drift check to cover every kernel, not the first one** — a list of kernels in the build script that the check script does not read is a silent gap. _Landing 17:_ `build-wasm.sh` and `check-wasm.sh` now share one kernel list, and the check caught the stale perturbation artifact immediately when the ABI grew.

38. **If a unit of work also determines parallelism, size it by the parallelism** — a tile is not only "how much work", it is "how many workers can have work at once". One tile is one worker, however wide the pool. _Landing 18:_ the coarse pass was a single 1024-sample tile, so the latency-critical pass used one of eight workers; tiling it to 16 took it from 1735ms to 612ms.
39. **An optimisation that measures as a no-op should not be shipped** — reasoning that a special case must be faster is not evidence. _Landing 18:_ specialising `fe_mul`'s normalisation for products of normalised mantissas looked obviously cheaper than the bit-extraction path and measured 114.1ms vs 115.3ms — identical. Reverted; the generic path is one thing to explain instead of two. (Compare rule 11: measure, do not derive.)
40. **Do not implement a named technique until its premise matches your design** — a technique carried by reputation comes with assumptions that may already be handled. _Landing 18:_ rebasing exists to stop a reference orbit's absolute error from invalidating deltas; this engine stores the orbit in `Floatexp` at converged precision and repairs cancellations exactly, so the premise does not hold. Zero glitches in 30k pixels across ten views says the same thing from the other side. The finding is recorded rather than the technique implemented (ledger row 34) — and when a control case fails to fire, say so instead of claiming the detector is proven.

41. **A validator that samples the wrong neighbourhood validates the wrong thing** — the sampled population must be the population the approximation will meet in production, and a radius is exactly the kind of quantity that can be wrong by a whole exponent without anything failing. _Landing 19:_ `offsetMagnitude` returned `|z|^2`, so the series validator sampled a 2^-200 neighbourhood on a 2^-100 view; every test still passed and the reported speedups were flattering. Pin the _radius_, not just the results it produces.
42. **A name that says magnitude and a body that returns a square is a bug waiting for a caller** — `offsetMagnitude` was used by exactly one caller, which passed it to a function whose parameter was called `maxOffset`, and nothing ever compared the two against the view. The fix is `sqrt`, and the rule is: when a helper's name commits to a unit, assert the unit somewhere.
43. **Validate an accelerator on the chained sequence, not one step of it** — a single jump can look excellent while ten in a row drift, because each re-anchors on an already-approximate value. BLA's validator simulates the jump sequence a pixel will actually take, comparing at every block boundary.

44. **A uniform field's _type_ is part of its contract** — an integer bit pattern written into a `vec2<f32>` slot is a denormal to the shader, and `i32(x)` truncates it to zero. Nothing errors; the value is simply wrong. _Landing 20:_ the perturbation kernel's step exponent was written with `ints[16] = e`, so a 2^-24 step reached the shader as 2^0 and counts agreed on 10/192 pixels. The habit that found it: **sweep the budget** — agreement that is bad at four iterations cannot be rounding, so the fault is structural.
45. **A sampling hole is not a fidelity choice** — when a fast engine is allowed to disagree with the oracle, the _set_ of pixels it disagrees on must be detected, not averaged over. The GPU kernel flags any pixel whose delta it cannot trust and hands it to the exact engine; a drift that is not flagged is a wrong answer, not a preview.

46. **When two APIs must agree on a refusal, the refusal belongs in one place** — "the flagged pixel is recomputed exactly" has to mean the same thing whichever GPU API the browser handed us, or the seam has a hole in it. _Landing 21:_ `repairFlaggedPixels` is shared by the WebGPU and WebGL2 backends; only the _test_ for a refusal differs (`-2` in count mode, a transparent pixel in colour mode), and each backend passes its own predicate.
47. **Port the convention with the algorithm** — a fragment shader's `gl_FragCoord` is bottom-up while a compute shader's `invocation_id` is top-down, and the reference point, the step sign and the row flip all move together. _Landing 21:_ WebGL2 measures its imaginary offset _from_ the reference downward (`uReferencePixel.y - gl_FragCoord.y`) and the shader says why; getting it wrong flips the image, which the differential pin catches immediately.

48. **A kernel's inputs are per-axis, and a `vec2` is one value** — packing `(hi, lo)` into a `vec2` halves the number of uniforms, which is fine until the kernel needs a second axis and quietly reads the first one twice. _Landing 22:_ the WebGL2 double-single kernel shared the L0 header and computed `cRe` and `cIm` from the same `uOrigin`/`uStep`, so every pixel got the same coordinate. The **non-degeneracy assertion** caught it: a collapsed render is indistinguishable from a legitimately uniform view, so "at least one pixel differs from its neighbour" has to be asserted where the oracle says the view varies.
49. **Order the dispatch by what the caller asked for, not by what is convenient to check first** — `exact` at a depth the wider kernel reaches must not be routed to a narrower engine because the _preview_ path would have taken it. _Landing 22:_ checking depth before quality sent `exact` at 2^-24 to the preview-only perturbation shader; the capability statement said the same wrong thing, so the pin that asserts the _stage_ is what exposed it.

50. **A bit-mask comparison of a signed quantity is a different question** — `i64x2_lt`/`i64x2_gt` in wasm SIMD compare _unsigned_ lanes, so with every exponent negative the largest-magnitude exponent looks like the largest value and the glitch test fires on everything. Bias both sides above the exponent range before comparing (the bias cancels). _Landing 23:_ the first paired kernel reported every pixel as glitched at iteration 1.
51. **`bitselect(a, b, mask)` keeps `a` where the mask is set** — the polarity matters, and a helper that mirrors a scalar `if` is exactly where it gets flipped. _Landing 23:_ all four selects in the paired `fe_add` were reversed, so any sum with a zero operand collapsed to zero — and for a real delta the imaginary part _is_ zero, so that was almost every sum. Both functions compiled, ran, and were wrong; the differential against the JavaScript carrier is what caught them.
52. **A refusal that shares a mask with another refusal has to be tested with both** — _Landing 23:_ orbit exhaustion set `exhausted_mask`, but the write path tested only `glitch_mask`, so pixels the reference could not reach were reported as _bounded_ — the one answer that is definitely wrong. Write the union explicitly.

53. **A carrier that reports less than the one it replaces is a regression in observability** — swapping implementations must not quietly drop what the caller could see. _Landing 24:_ the JavaScript jump carrier returns `blocks` and `refined`; the WASM kernel initially returned neither, so every pixel "differed" in the differential. Fixed by exporting the accounting rather than by weakening the comparison.
54. **When two implementations must agree, put the shared _inputs_ in one place** — the BLA coefficients are composed in JavaScript and uploaded, so the kernel applies the same numbers the JavaScript carrier does. Composing them on both sides would have meant two rounding paths and a tolerance where a bit-comparison was available. _Landing 24._

55. **Pair the data, not just the arithmetic** — the win in a paired loop comes from whatever both lanes would otherwise compute twice. Here that is the reference value _and_ the BLA table entry, so the loop reads one `(A, B)` and applies it to two lanes. Pairing the arithmetic while reading the table per lane would have won much less. _Landing 25._
56. **A masked state machine must mirror the scalar loop's _order_, not only its maths** — freezing finished lanes with masks is what makes pairing possible, but the recording of `iterations`, `magnitude`, `blocks` and `refined` then has to happen at exactly the point the scalar version records them, or the outputs differ on precisely the pixels where a lane finished early. _Landing 25:_ the two loops agree bit for bit, including on the view where every pixel escapes inside a jumped block.

57. **A rectangle inside a larger buffer has an extent, not a stride-multiple** — a view sized `rows * stride` is only correct when the buffer starts at the rectangle and is exactly as wide. _Landing 26:_ the worker's blit had always seen tile-sized scratch buffers, so the overrun stayed invisible until targets became rectangles inside a pass image; it then failed loudly (`Invalid typed array length`) for any tile near the image's right edge. The extent is `(rows - 1) * stride + columns * 4`.
58. **Zero-copy changes what the cache can hold** — writing pixels into the pass image leaves nothing for a tile cache to store, so the two goals conflict and one has to be chosen per path. _Landing 26:_ the uncached path writes into the pass image; the cached path shares the _tile's_ buffer instead, which still removes a copy and keeps the cache honest. Naming which path is which is part of the design, not an implementation detail.

59. **A cost model that is never fed is a decoration** — a planner that accepts a measurement nobody supplies will quietly never choose the option that depends on it, and every test of the _pricing_ still passes. _Landing 27:_ `planView` had priced `measuredSeriesSkip` since the ladder landed and nothing had ever produced one, so the series stage was unreachable in the product. The fix is a seam from the renderer back to the planner, and a pin on the _loop_, not on the arithmetic.
60. **Measure against the shape of the work, not the exact input** — a measurement keyed on the exact centre would be discarded on the next pan, which is precisely when it is useful. _Landing 27:_ the key is scale, canvas and budget, so views a pixel apart share what was measured.

61. **One styling seam: tokens, not literals** — every chrome value comes from a `--orion-*` token; a raw hex or spacing literal in presentational code is drift waiting to happen. _Incident (landing 46):_ the first UI wiring left the hidden scratch canvas **visible**, because a broad `.orion-viewport canvas { display: block }` rule has higher specificity than `.orion-scratch { display: none }`. Nothing looked broken visually; the browser lane's strict-mode `canvas:visible` locator resolving to two elements is what caught it, and that locator is now the tripwire for the class.

62. **A resize keeps the place and the zoom** — re-expressing a view at a new pixel grid must preserve the complex-plane centre and the per-pixel scale; change either and the image jumps or zooms under the user when they drag a window edge. `resizeView` does exactly that, recomputes the complex width through `makeView` so validation still runs, and the honest rounding (a few ulps of width) is documented like navigation's. _Landing 46._

63. **A cheap draw is not a cheap pass** — a GPU dispatch over a big tile is cheap, but the CPU work the tile triggers (here: flagged-pixel repair) scales with the tile's area, so the latency-critical pass must be bounded by the expensive side rather than the cheap one. _Incident (landing 49):_ the coarse pass used a 1024x1024 tile because "a GPU wants one draw call"; at a deep view whose reference orbit was exhausted, every pixel was flagged and the synchronous repair took **54.9 s** before the preview could paint — the pass that exists to land first was the most expensive one.

## Do not / do instead

| Do not                                                   | Do instead                                       | Incident / why                                              |
| -------------------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| Near-duplicate helpers                                   | One seam + pin                                   | Drift is invisible at birth                                 |
| Claim done without gate                                  | Re-run `scripts/gate.sh` after land              | Author verify ≠ independent verify                          |
| Mix package managers                                     | `pnpm` only (see AGENTS.md)                      | Lockfile / script drift                                     |
| Invent product features                                  | Follow the directed product scope (ledger row 2) | Scope creep; briefs come from Arnd                          |
| Compare values across representations                    | Assert the invariant in the exact type           | Landing 2 false failure: rounded double vs exact threshold  |
| Trust a pin without breaking it once                     | Mutation-check it                                | A pin that cannot go red is decoration                      |
| Derive working precision from a built view               | Derive from the scale, then validate the view    | Circular: a too-coarse view cannot report what it needs     |
| Assume `cargo` is on PATH                                | Call `~/.cargo/bin/cargo` explicitly             | rustup installs outside the default PATH                    |
| Time GPU work on this box                                | Measure on real hardware via the HUD             | SwiftShader is 100–1000× slower; timings are noise          |
| Test only typical magnitudes                             | Include negative values and extreme gaps         | Landing 3: two mutations survived until those pins existed  |
| Pin a hand-derived numeric prediction                    | Measure it first, then pin the measured property | Landing 3: the derived prediction was simply wrong          |
| Pin a threshold via a total-cancellation case            | Pin just inside and just outside the threshold   | Landing 4: `0 < x` fires under any threshold                |
| Widen a tolerance to make a test pass                    | Trace the discrepancy, then set from measurement | Landing 4: unexplained 6e-6 became a documented mechanism   |
| Assume a test view is non-degenerate                     | Assert escapes / trusted pixels occurred         | Landing 4: a 3-depth survey proved nothing at `escaped=0`   |
| Hard-code a chrome colour/spacing in a component         | Reference an `--orion-*` token                   | Landing 46: the one styling seam is `tokens.css`            |
| Resize by rebuilding the view from its centre as a float | `resizeView` keeps the exact centre + scale      | Landing 46: a float rebuild would silently deepen the place |
